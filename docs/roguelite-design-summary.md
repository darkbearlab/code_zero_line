# Code: Zero Line — Roguelite 設計概要

> **用途**:給 IDE 端 Claude Code 看的實作參考。
> 跳過討論過程,只記實作會用到的設計決定。
> 細節討論與未決問題見 `open-questions.md`,整體願景見 `roguelite-design.md`。

---

## 1. 核心 fantasy

**玩家是被空投到前線的指揮官**,接手一支已經編制好的小隊,參與對固定目標的多階段侵攻。

世界觀關鍵句:**玩家是這世界中唯一在做事的人**。其他單位會打仗、會死,但只有玩家親自參與的任務會推進整個 campaign 的核心進度。

---

## 2. 三層遊戲循環

```
[Campaign 層] ─── 整個遊戲過程,以「終局戰鬥打贏」為結束
   │
   └─ [戰役回合 層] ─── 設置 → 戰術 → 解決,單位是一個「戰役回合」
         │
         └─ [Run 層] ─── 玩家在戰術階段選的那一個任務,可能是 1 關到多關
               │
               └─ [Mission 層] ─── 一場戰鬥(現有 BattleScene 處理)
```

---

## 3. Campaign 層

### 3.1 探索拓撲

- 主線區域 = 全部區域,**沒有支線**
- 區域三階段:**突破口 → 橋頭堡 → 佔領區**(不用百分比)
- 佔領區仍會出現衝突任務(常規殲滅),不再產情報
- 終局是獨立區域,需要解鎖才出現

### 3.2 終局解鎖路徑

兩階段:

**第一階段:解鎖**
- 終局是升級選單最後一項,以**作戰情報**購買

**第二階段:挑戰路徑**(解鎖後二選一達成)
- **正規路徑**:所有主線區域達到「佔領」狀態
- **速通路徑**:支付作戰情報跳過佔領要求(給 RTS 狂人用)
  - 速通價格設計原則:比正常推圖到終局所獲得的情報還少(否則速通是虧的)

### 3.3 終局戰鬥本身

- 攻擊區域只有 1 關,比平常戰鬥要長
- **無犧牲打 / 無高價值目標 / 無情報獎勵**(無線電靜默,東西傳不出來)
- 打贏 = campaign 結束 → 計分表攤開

### 3.4 計分表

- Campaign 全程累積,完成戰役後一次攤開,設計給玩家截圖分享
- 記錄項:死多少人、獲得 / 花費多少各種貨幣、總 run 數
- 對標:Slay the Spire 的結算頁

### 3.5 開場

第一場 run 是「**偵查部隊突圍回總部**」——幾乎一定能贏的教學關。突圍成功 → 總部展開侵攻 → 進入主 campaign。

開場「資訊送回後方」與終局「無線電靜默」形成敘事對稱。

## 4. 戰役回合層(三階段)

```
[戰役設置階段]
  ├─ 抽出本回合所有可選任務(浮動 3-5 個)
  ├─ 每個任務分配一隊出擊士兵(來自池子)
  ├─ 每個任務顯示成功率(fuzzy:高/中/低)
  └─ 玩家選 1 個接手指揮

[戰術階段]
  └─ 你接手的那一場 → Run 層處理(BattleScene + 多關)

[戰役解決階段]
  ├─ 你接手的任務 → 戰鬥結果(隊員命運看戰鬥結束時狀態)
  └─ 你沒接手的任務 → 骰成功率,結算如下表
```

### 4.1 任務狀態與隊員命運

| 任務狀態 | 結果 | 隊員命運 | 玩家獎勵 |
|---|---|---|---|
| 接手 + 戰鬥贏 | 戰術勝利 | 看戰鬥結束時狀態,活的回池 | 作戰 70% + 區域 30% |
| 接手 + 戰鬥輸 | 戰術失敗 | fuzzy 判定,本來活的也可能沒回來 | 部分(看打贏的關卡) |
| 沒接(放棄) | 任務失敗 | 全員死亡 | 無 |
| 沒接 + 任務骰贏 | 任務成功 | 隊員回池(出擊次數+1) | 區域情報(30% 那份) |
| 沒接 + 任務骰輸 | 任務失敗 | 隊員從池中永久移除 | 無 |

### 4.2 池子流動

**修正(2026-04-30)**:之前認為「沒接任務 + 失敗 = 永久死亡」就是自然汰換、不需補員 — 實作後發現會單調下沉，應主動補員。

**現行機制**:
- 池子目標 = **30 人**(`POOL_TARGET`)
- 角色 floor = **3 officer / 8 specialist / 19 regular**(大致 1:3:7),officer floor 確保每個任務都有得抽
- 補員時機:`newCampaignState`(開新檔)+ `advanceCampaignAfterRun` 末尾(每場結束)
- 候補來源:bundled templates 按 `recruitRole` 分組 seeded random
- 池子上限就是 30 — 補到 30 後不會再多;若初始池已 > 30 也不會縮(防禦性)

## 5. Run 層

### 5.1 Run 結構

玩家在出擊前選兩個維度:
- **攻擊強度**:對應敵人強度
- **攻擊深度**:對應攻擊區域,也決定要打幾關

```
[Run 開始 → 中間關卡(殲滅) → Hub → ... → 最終關 → Run 結束]
```

- **中間關卡**:通常是常規殲滅
- **最終關**:任務類型由攻擊區域佔領情形決定(常識比例)
- **Hub**(關之間):Hades 式門選,呈現為「隊員與指揮官對話」(指揮部不知道前方,前線回報)

### 5.2 Boon 種類(Hub 選項)

包含但不限於:
- 指定隊員數值提升
- 獲得額外武器分配給隊員
- 一次性使用技能
- 增援
- Meta 資源

### 5.3 犧牲打分歧任務

- 在 Hub 選擇時,隊員可能回報「前方有預期外的高價值目標」
- 玩家可選擇是否挑戰
- 挑戰成功 → meta 進度,或之後幾個 run 的增益
- 機制上是 boon 的一種變體(高風險高回報選項)

### 5.4 最終關特殊目標

每個 run 的最終關目的可能不同,run 開始前告訴玩家,讓玩家準備對應裝備/隊員/武器。**特化任務(暗殺、破壞)時玩家可從池子置換 1-2 個槽**(中間關卡完全不選)。

待決細節:預告的時機(選 UI 中 / 選之後)、能否重選、清單規模、中間關是否也預告。

## 6. 小隊系統

### 6.1 玩家視角

**玩家不組隊**。每個 run 接手一支從池子逐槽抽出來的小隊。例外:特化最終關時可換 1-2 個槽。

### 6.2 逐槽抽結構

- **槽數**:有 RNG,榮譽強化後傾向骰到較多槽
- **每個槽**:有性質類型(officer / regular / specialist),從對應 sub-pool 抽
- **池子內容**:強化後高素質比例提高
- **重抽隊員**:全局升級之一,**花榮譽**

### 6.3 老兵系統

- 打贏的隊員回池,**追蹤出擊次數**
- 任務名單顯示時,曾跟隨玩家的隊員會 highlight
- **老兵成長**:出擊次數每 N 次 → 素質 +1(到上限為止)
  - **不收費,自動**——情感引擎不能收費
- **池子強化會提升所有池子內的人**(包含老兵)
- 戰死處理:run 結算殺報名單,出擊次數高的特別標示

## 7. Meta 經濟

### 7.1 三種貨幣

| 貨幣 | 主要用途 | 來源 |
|---|---|---|
| **作戰情報** | 戰術知識升級、解鎖新敵人 / 區域、終局解鎖、速通 | 玩家親自打贏(70%) |
| **區域情報** | 解鎖新區域(主要),5:1 兌換作戰情報 | 親自打贏(30%) + 沒接任務骰贏(全部) |
| **榮譽** | 池子強化、武器層級、重抽小隊、任務成功率、抽槽數 | 完成 run 為主 |

### 7.2 情報經濟公式

```
任務基底情報 = 任務類型基底值 × 難度倍率(攻擊強度)

玩家親自打贏:
  作戰情報 = 任務基底情報 × 70%
  區域情報 = 任務基底情報 × 30%

沒接的任務骰贏:
  作戰情報 = 0
  區域情報 = 任務基底情報 × 30%(只拿「30% 那份」)
```

**世界觀解讀**:30% 區域情報是世界本身產的(任務完成就有);70% 作戰情報是玩家親自參與才產的。

### 7.3 兌換

**區域情報 → 作戰情報 5:1**,單向。反向不需要(作戰情報能買所有東西)。

### 7.4 死亡時的貨幣損益

| 結局 | 作戰情報 | 區域情報 | 榮譽 | 探索進度 |
|---|---|---|---|---|
| 完成 run | ✅ 取得 | ✅ 取得 | ✅ 取得(主要來源) | ✅ 推進 |
| 全滅但有打贏關卡 | ✅ 逐關累積 | ✅ 逐關累積 | ❌ | ❌ |
| 全滅且無打贏關卡 | ❌ | ❌ | ❌ | ❌ |

**核心精神**:絕大多數 meta 進度來自完成 run,不是堆屍。死亡的真正懲罰是失去 run 完成獎勵這筆大收入。

**設計約束**:完成 run 的獎勵必須遠大於過程中累積的情報。具體比例 sim 階段調。

## 8. 多人解鎖

完成第一個 run 後解鎖。可玩內容包含:已解鎖的全局進度 + 在贏過的 run 中出現過的敵人 + 對應地圖。

---

## 9. 敘事強度

**輕敘事,鉤子充足**。已建立的鉤子:
- 偵查部隊突圍開場
- 隊員與指揮官對話的 boon 框架
- 戰役階段「沒接任務的人會死」
- 老兵出擊次數累積
- 無線電靜默終局

設計原則:**不再增加感情方面的深度**。鉤子已夠,讓玩家自編故事。

---

## 10. v1 範圍提醒

- 槽數範圍、攻擊深度級數、最終關預告時機 = **留待 sim 階段調**
- 任務類型基底值、難度倍率、老兵成長速率 = **留待 sim 階段調**
- 池子上限 = 暫不設,觀察後再決定
- 階級系統、戰績紀錄 = **後期再加**,v1 用純數字

## 11. 引擎重用速查

從現有的 `code_zero_line` 引擎遷移,**核心不需要改**:

- BattleScene 接受 `initialState` → mission 生成器產出
- Scenario 已是 discrim union → 加新 mission types 直接 extend
- Sim CLI 改用途:從「PvP AI 對抗」變成「PvE 平衡回歸」(每個 mission type / 攻擊強度的勝率)
- Editor 維持原樣(手作地圖 + 程序化變體)
- AI controller 從 PvP 對手變成 PvE 敵方

新增模組(都是 additive,不動現有目錄):

```
src/
  campaign/      ← Campaign 層永久狀態 + localStorage
  meta/          ← 三貨幣 + 升級樹 + 老兵追蹤
  rounds/        ← 戰役回合層(設置/解決階段邏輯)
  runs/          ← Run 層狀態機
  missions/      ← Mission 生成器 + 任務型定義
  presentation/scenes/
    TitleScene
    CampaignMapScene  ← 探索拓撲視覺化
    RoundSetupScene   ← 戰役設置(任務選單)
    RoundResolveScene ← 戰役解決(沒接任務骰結果)
    RunSetupScene     ← Run 設定(攻擊強度 × 深度)
    HubScene          ← 關之間 boon 選擇(隊員對話 framing)
    RunResultScene    ← Run 結算(殺報名單)
    MetaScene         ← 升級樹 / 計分表 / 池子
```
